# Ядро работы с геодезией 

## 1. Выявленная проблема и узкое место
В современных горно-геологических информационных системах (ГГИС) и корпоративных платформах хранения геоданных (таких как «Плита») критическим узким местом является **камеральная обработка и геометризация пространственных данных**. 

При ручном или классическом скриптовом подходе на Python расчет регулярной 3D-сетки блоков (вокселей) и инклинометрия (расчет 3D-траекторий) вееров скважин занимают от нескольких часов до дней [context]. Это парализует оперативную работу геолога и делает невозможным динамическое планирование ГРР. 

**Решение:** Перенос тяжелых геометрических и тригонометрических расчетов на уровень нативного компилируемого системного языка (Rust) с прямой интеграцией в пространственный индекс СУБД PostGIS [context].

---

## 🌐 2. Концепция ИИ-интеграции через MCP (Model Context Protocol)
Проект спроектирован с учетом интеграции в современные мультиагентные ИИ-экосистемы. Расчетное ядро на Rust может функционировать как **MCP-сервер (Model Context Protocol)**.

Это позволяет внешним LLM-моделям (геоагентам) и аналитическим ИИ-системам не просто «болтать», а использовать наше Rust-ядро как строго типизированный инструмент (Tool) для выполнения низкоуровневых операций над недрами:
1. ИИ-агент запрашивает через MCP расчет блочной модели для участка [context].
2. Rust-ядро выполняет наносекундный расчет и забивает PostGIS [context].
3. ИИ-агент получает стерильный структурированный контекст недр для дальнейшей оптимизации сети бурения [context].

## 🧮 3. Математическая суть методов и примеры реализации

### А. 3D Инклинометрия и расчет веерного бурения
Скважины бурятся веерами с одной точки стоянки (рига) под разными зенитными углами [context]. Ствол представляет собой пространственную кривую `LineString Z` в местной проекционной системе координат ГГС РФ **EPSG:28415** [context].

Нативное Rust-ядро рассчитывает траекторию ухода ствола вглубь по тригонометрической схеме:
\[\Delta X = L \cdot \cos(\alpha), \quad \Delta Z = L \cdot \sin(\alpha)\]

*Пример нативной сборки 3D-линии ствола в PostGIS:*
```rust
// Расчет дельты координат на основе длины (max_depth) и зенитного угла
let delta_x_meters = max_depth * angle_rad.cos();
let delta_x_deg = delta_x_meters / 111000.0; // перевод в градусы WGS84
let target_z = rig_elevation - (max_depth * angle_rad.sin());

// Нативный параметрический инсерт 3D LineString Z
sqlx::query!(
    r#"
    INSERT INTO sandbox_simulation.synthetic_drillholes (id, body_id, hole_code, easting, northing, elevation, max_depth, geom_line)
    VALUES ($1, $2, $3, $4, $5, $6, $7, 
            ST_SetSRID(ST_MakeLine(ST_MakePoint($4, $5, $6), ST_MakePoint($8, $9, $10)), 4326))
    "#,
    dh_id, body_id, code, rig_x, rig_y, rig_elevation, max_depth, (rig_x + delta_x_deg), rig_y, target_z
);
```

### Б. Процедурное моделирование и 3D Вокселизация ГKЗ
Для симуляции реалистичной топологии рудного тела и хаотичных перетеканий содержаний полезного ископаемого (золота Au) ядро использует **3D Шум Перлина (`Perlin Noise`)** [context]. Пространство нарезается на регулярные кубы (воксели) размером 6 метров [context].

Для каждого вокселя рассчитывается 3D евклидово расстояние до ближайшего инклинометрического ствола веера:
\[D_{3D} = \sqrt{(\Delta X)^2 + (\Delta Y)^2 + (\Delta Z)^2}\]

*Пример автоматического ГКЗ-комплаенса и генерации вокселя в Rust:*
```rust
// Генерация "перетекающего" содержания золота с ураганными скачками через 3D шум
let noise_grade = perlin.get([e_steps * 2500.0, n_steps * 2500.0, current_z * 0.1]);
let raw_grade = ((noise_grade + 1.0) * 4.0) - (z_layer.abs() as f64 * 1.5);
let grade_au = if raw_grade < 0.2 { 0.05 } else { raw_grade };

// Оценка плотности разведочной сети под регламенты ГКЗ РФ
let category = if grade_au <= 0.2 { "Пусто" } 
               else if min_dist <= 35.0 { "C1" } // Промышленная категория
               else if min_dist <= 75.0 { "C2" } // Оцененные запасы
               else { "Брак" }; // Зона неопределенности (цель для ИИ-оптимизатора)

// Инсерт 3D Bounded Box куба в PostGIS через нативный ST_MakeEnvelope
sqlx::query!(
    r#"
    INSERT INTO sandbox_simulation.synthetic_voxels (id, body_id, voxel_east, voxel_north, voxel_elevation, gkz_category, geom_cube)
    VALUES (\$1, \$2, \$3, \$4, \$5, \$6, 
            ST_Force3D(ST_SetSRID(ST_MakeEnvelope(\$3 - \$7, \$4 - \$7, \$3 + \$7, \$4 + \$7), 4326)))
    "#,
    voxel_id, body_id, e_steps, n_steps, current_z, category, 0.00005 // дельта полуразмера кубика
);
```
